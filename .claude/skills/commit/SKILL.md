# Commit

## 手順

### 1. チェック

```bash
pnpm typecheck
```

- Prisma スキーマを変更した場合は先に `pnpm db:generate` (= 型が古いまま通ってしまう)
- 型エラーがあれば修正する。**通るまでコミットしない**
- ドキュメント / 設定ファイルのみの変更ならスキップ可

**`pnpm typecheck` が唯一の静的ゲート。** akashic には lint 設定もテストも無く、`next.config.ts` は `typescript.ignoreBuildErrors: true` なので **ビルドが通っても型は壊れていることがある**。`pnpm build` で代用しない。

### 2. 変更内容の確認

```bash
git status
git diff --staged
git diff
```

- 変更内容をユーザーに提示する
- コミットに含めるファイルを確認する
- **ユーザーの許可を得てからコミットする**

### 3. コミットメッセージの作成

#### 絵文字プレフィックス (必須)

akashic で実際に使われているもの (= 直近 200 コミットの実測):

| 絵文字 | コード | 用途 |
|---|---|---|
| 🐕 | `:dog2:` | 機能追加・改善 (最頻出) |
| 🐟 | `:fish:` | バグ修正・挙動修正・小さな UX 調整 |
| 🎈 | `:balloon:` | パフォーマンス改善・インフラ/設定変更・リファクタ |
| 🍨 | `:icecream:` | ドキュメント更新 (`docs/api.md` / 設計書) |

必要になったら hnt42-project 共通表から足す:

| 絵文字 | コード | 用途 |
|---|---|---|
| ⚽ | `:soccer:` | テスト追加・修正 |
| 🤖 | `:robot:` | CI/CD・自動化・スキル/エージェント |
| 🫧 | `:bubbles:` | 依存・設定・環境変更 |
| 🩰 | `:ballet_shoes:` | DB スキーマ・マイグレーション (Prisma schema / RLS / SQL) |

`:bug:` は古い時期のバグ修正で使われていたが、現在は **`:fish:` に統一済み**。新規に使わない。

#### メッセージ構成

```
:emoji: 何を変更したか (日本語・1 行)

なぜこの変更が必要か / 何が壊れていたか (数行の散文)

Co-Authored-By: <システムプロンプトで指定されたモデル名> <noreply@anthropic.com>
Claude-Session: <セッション URL>
```

- タイトルは **何を (What)** したかを簡潔に。バグ修正なら括弧で症状を添えると読みやすい
  (例: `:fish: ダッシュボードのトーク差分を新奈のみに集計（全メンバーを数えていた不具合）`)
- 本文には **なぜ (Why)** を書く。「何を変えたか」は diff を見れば分かるが、「なぜ変えたか」はコミットメッセージにしか残らない
  - バグ修正なら: 何が起きていたか → 原因 → どう直したか → 直った結果の数値
  - 機能追加なら: 何のための機能か → 設計書があればパスを添える (例: `設計書: docs/coverage-design.md`)
- メッセージは日本語
- `Co-Authored-By` のモデル名は **セッションのシステムプロンプトが指定する表記をそのまま使う** (= このファイルにハードコードしない)

### 4. コミット実行

```bash
git add <files>
git commit -m "$(cat <<'EOF'
:emoji: タイトル

なぜこの変更が必要か。

Co-Authored-By: ...
Claude-Session: ...
EOF
)"
```

## コミット分割の原則

**1 コミット = 1 つの絵文字プレフィックスがぴったりはまる単位** にする。
1 コミットに複数の絵文字が必要になるのは、分割が足りないサイン。

特に個別コミットにするもの:

- **スキル**: 1 スキル = 1 コミット (例: `commit/SKILL.md` と `worktree/SKILL.md` は別)
- **ドキュメント**: 1 ドキュメント = 1 コミット
- **Prisma マイグレーション**: スキーマ変更とそれを使う実装は分ける (= `:ballet_shoes:` と `:dog2:`)

設定ファイルの追加 (`tsconfig.json`, `next.config.ts` 等) は関連するものをまとめてよい。

## 注意事項

- **ユーザーの明示的な許可なくコミットしない**
- **`git add -A` / `git add .` は使わない。** ファイルを個別に指定する
- `.env` / API キー / `SUPABASE_SECRET_KEY` をコミットしない
- **適用済みの migration を後から編集しない。** RLS ポリシー等の手書き SQL を migration に足すのは akashic の通常運用だが、それは**新しい migration ディレクトリを作って**行う (= 適用済みファイルを書き換えると本番と履歴が食い違う)
- pre-commit hook が失敗した場合は `--amend` せず、新しいコミットを作成する
- 変更がない場合は空コミットを作成しない
