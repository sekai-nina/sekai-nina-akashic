# 動画の時間的な裏付けを評価する（オフライン試作）

`scripts/evaluate-video-evidence.py` は、保存済みのスコアと人が動画全体に付けた正解から、自動タグの規則を比較する。顔モデルの実行や DB 更新はしない。評価と、本番へ採用する時間条件の記録。

## 本番への採用判断（2026-11-21）

ユーザーが取りこぼし2本を確認し、許容範囲と判断したため、時間条件を坂井新奈の動画だけに採用する。固定条件は類似度0.4・検出スコア0.5・候補間の差0.05・同一匿名トラックの異なる0.5秒枠で2回以上・継続0.5秒以上・検出間隔1秒以内。これは5分割で4分割が選んだ条件であり、81→16・取りこぼし2の成績は分割ごとに条件選択した手順の成績のまま扱う。

2本目 `7589258105087610132` は、ユーザーによれば48秒付近に約1秒登場する。短い登場そのものが条件未満なのではなく、顔候補・追跡・候補差の連続した裏付けを作れなかった例。登場区間の追記で評価用の正解・分割・閾値を変更しない。

APIは実際のAsset.kindで動画を判別し、坂井新奈の候補は版付きの `videoEvidence` が不足すると確認待ちにする。旧ワーカーからの最高点だけでも自動確定しない。画像と他メンバーは従来どおり。人が確定・却下した判断は既存の引き継ぎ規則を維持する。

ワーカーは画像を `buffalo_l@3`、動画を `buffalo_l@3:video1` で記録する。queueの `videoModelVersion` で動画だけを再走査し、画像を一斉に処理し直さない。APIを先に配布し、旧ワーカーを停止して新ワーカーへ切り替える。推論と再処理の完了は別なので、反映状況は運用記録で確認する。デプロイ前の200本スコア再生では、本番の裏付け集計が評価関数と200/200本で一致した。

## 200本の評価結果（2026-11-21）

ユーザーが正解を付けた200本（登場39・非登場161）の走査が完了した。失敗0本。以下は、既知の回帰用3本を除き、各動画を条件選択から外した5分割評価197本（登場37・非登場160）の結果。閾値付近を多めに抽出しているので、日常の全動画に対する発生率とは区別する。

| 方式 | 非登場を登場とした件数 / 160 | 登場を自動判定できなかった件数 / 37 |
|---|---:|---:|
| 従来：最大24コマの最高点 ≥ 0.4 | 81 | 0 |
| コマ数だけ増やし、最高点 ≥ 0.4 | 115 | 0 |
| 固定の0.5秒条件 | 32 | 1 |
| 継続時間・類似度・候補間の差を調整用だけで選択 | 16 | 2 |
| 固定の2秒条件 | 2 | 7 |

時間的な裏付けは誤検出を大きく減らした。コマを増やして最高値だけを見ると、誤検出はむしろ増えた。2秒の固定条件は取りこぼしが多い。条件選択手順の197本評価では、自動で登場とした51本のうち35本が正解（precision 68.6%）。抽出確率を補正した探索的 precision は75.0%で、**誤検出は残る。ユーザーは取りこぼし例を確認して採用を判断した（冒頭参照）。** 自動判定しない正例は非登場と断定せず、確認待ちになる想定。

### 条件選択と独立に残した41本

最初に固定した最終評価用41本（登場9・非登場32）では次の結果だった。時間条件の調整候補は、類似度0.4・0.5秒以上・異なる0.5秒枠で2回以上・候補間の差0.05。197本の5分割では、5分割中4分割がこの条件、1分割は候補間の差なしを選んだため、197本の成績は単一条件ではなく条件選択手順の成績である。

| 方式 | 誤検出 / 32 | 自動判定できなかった正例 / 9 |
|---|---:|---:|
| 従来 | 21 | 0 |
| 固定0.5秒 | 7 | 1 |
| 調整用で選択した時間条件＋候補間の差 | 4 | 1 |
| 調整用で選択した動画用最高点閾値0.55 | 3 | 1 |

調整用の基準では、最高点閾値0.55が僅差で選ばれた。ただし最高点閾値の選択手順は、5分割中2分割で「補正したrecall95%以上と回帰例の維持」を満たす閾値を選べず、従来方式へ戻す事前の規則を含めて誤検出35・取りこぼし4になった。これは単一閾値0.55の成績ではない。41本の僅差だけで方式を決めず、分割ごとの不安定さも評価する。

正例9本の最終評価だけでは不確かさが大きい。近似重複は未確認で、同一SHA-256の除外までを実施した。同じアーカイブ・同じモデル・同じ参照スナップショットでの結果であり、登場確率が校正できたことを示さない。本番の判定・タグ・参照は変更していない。

### 動画の非登場ラベルから作る負例の追加探索

人が「動画全体に対象人物はいない」と確認した動画の顔は、対象人物ではない手本にできる。一方、登場動画に映る各顔を本人の正例にはしない。既存の負例除外と同じ幅0.05を固定し、各分割の学習側の非登場動画だけから手本を作った。

保存済み最高点の顔160件（動画200本中、候補なし40本）を取得し、現在の固定した参照で再判定した。各動画を手本から外した197本評価で、同じピーク顔入力の baseline は誤検出79・取りこぼし0、負例追加後は誤検出72・取りこぼし0だった。追加効果は限定的。これは全フレーム版とは違う入力を使った別実験であり、81→16の表と直接比較して優劣を判断しない。既に結果を見た同じ200本を使った追加探索なので、新しい独立テストとも呼ばない。

## 比較する規則

旧方式: 最大24コマ・最小間隔1秒の従来の採取位置で、顔検出スコア0.5以上かつ対象候補の類似度0.4以上が1コマでもあれば自動タグ。

2秒条件（CLIの既定）: 同一の匿名追跡IDで、類似度0.4以上・顔検出スコア0.5以上が、異なる1秒枠に3件以上、最初と最後の間隔2秒以上続いた場合だけ自動タグ。検出間隔の上限は2秒。

0.5秒条件（短い登場を含む今回の調整案）: 同じスコア閾値で、同一の匿名追跡IDの検出が異なる0.5秒枠に2件以上あり、最初と最後の間隔が0.5秒以上の場合。検出間隔の上限は1秒。

いずれも時間枠の原点は区間の先頭。動画の絶対秒の境目で採否が変わらないようにする。画面切替、同じ追跡IDの候補が変わる、スコアが閾値を下回る場合は区間を切る。追跡IDなしの検出は自動タグの裏付けにしない。

- 上記の数値は仮説。検証用データで選び、別のテスト用動画で一度評価する。
- 近接コマを独立した確率として掛け合わせない。出力は規則の判断であり、校正された登場確率ではない。
- 自動タグを付けない場合は確認待ち。短い登場を非登場と断定しない。動画全体の平均を使わないので、長い動画内の数秒の登場も評価できる。
- 似た別人が継続して高スコアになる誤りはこの規則だけでは解決しない。顔のぼけ・大きさ・他候補とのスコア差の評価も未実装。
- 旧方式のスコア抽出と同じモデル・参照を固定して比べる。再推論する場合、評価動画自身から得た確定・却下の参照を除外し、関連する切り抜きも同じグループにする。

## 入力

JSONL の1行を「動画 × 対象候補」1件にする。実データは Git に入れず、`reports/video-evidence/` に置く。

```json
{"videoId":"example-1","targetId":"person-A","groupId":"original-1","modelVersion":"fixed-model","referenceVersion":"held-out-refs-1","split":"validation","durationSec":10,"label":true,"labelSource":"human-full-video-review","frames":[{"t":0,"faces":[{"trackId":"anonymous-track-1","predictedEntityId":"person-A","similarity":0.6,"detScore":0.9}]},{"t":1,"faces":[{"trackId":"anonymous-track-1","predictedEntityId":"person-A","similarity":0.58,"detScore":0.9}]},{"t":2,"faces":[{"trackId":"anonymous-track-1","predictedEntityId":"person-A","similarity":0.61,"detScore":0.9}]}]}
```

`label` は動画全体で登場が確認されたら true、全体を確認して非登場なら false、未確認は null。顔1件を却下しただけで動画全体を false にしない。自動タグや書き手タグも正解にしない。

`frames` には採取した全コマを時刻順に入れ、顔がないコマも `faces: []` として残す。`sceneCut: true` はそのコマの直前に画面切替があることを示す。`trackId` は人物名・推定メンバーIDではなく、別工程で顔を時間方向に対応付けた匿名ID。評価スクリプト自身は追跡しない。予測名を追跡IDに流用すると別人の検出が合算される。

採取スクリプトの追跡は位置の重なり（IoU ≥ 0.1）、顔特徴量の連続性（cosine ≥ 0.6）、経過時間 ≤ 1.1秒で1対1に対応付ける。推定メンバー名は追跡に使わない。画面切替は縮小した画面の平均画素差を使う試作なので、見逃し・過分割の可能性がある。

`legacySample` は従来の採取コマ、`temporalSample` は0.5秒間隔の採取コマ。両方を区別して比較する。単純に採取数が増えたことによる最高値の変化を、集約方法の改善と混同しない。両フラグを省いた手製入力では、そのコマを両方式で使う。

48秒の動画は可変fpsのため、OpenCVのランダムシークで末尾の読み出しに失敗した。`ffprobe` で全コマの実時刻を取り、順番にデコードする方式にした。旧方式は従来と同じ要求フレーム番号、新方式は実時刻に基づく0.5秒間隔で採取する。可変fpsに対するデコード方法は本番と異なるため、本番の過去の結果の完全再現ではない。モデルと参照も今回固定したスナップショットを使う。

`groupId` は元動画・転載・切り抜きをまとめる。同じ動画や同じグループの validation / test への混入、同一動画×候補の重複は拒否する。モデル・参照の版は入力に必ず記録する。

既存ワーカーは最大24コマ・最小間隔1秒なので、長い動画ほど間隔が広がる。試作の2秒の間隔上限に合わない採取では、候補周辺の追加採取が必要。採取条件を揃えず結果を比較しない。

2秒条件の比較は、最後のコマンドから4つの条件引数を除き、出力先を `comparison-conservative.json` にする。

エクスポートは `DIRECT_URL` の存在を確認し、`READ ONLY` トランザクションと明示的な public / internal フィルタを使う。候補3本以外の元動画は取らない。参照は25,000件、動画は1本200MB、採取は1本10分以内に制限する。取得・採取とも無限リトライしない。DB接続とデコーダーは終了時に閉じる。特徴量・動画・結果は Git に入れない。

`--labels` は動画IDと対象IDで正解を結合する。時系列側の正解・グループ・split と矛盾すれば停止する。正解だけを入力して評価することはできず、対応する全コマの時系列が必要。

出力は validation / test 別の TP・FP・FN・TN、precision、recall、偽陽性率と各動画の判断・継続時間。正解不明は集計から除外し、分母0は null とする。FN は「登場しているが自動タグにならない」件数で、確認待ちも含む。

正例だけ、負例だけ、または少数の偏ったサンプルで改善を確定しない。誤検出の減少と、短い登場の取りこぼしを両方見る。反例を加えて規則を変えたら validation として扱い、同じ動画を最終 test の成績として報告しない。

```sh
# 母集団のスナップショットを取得（既存の評価セットを更新するときは版を分ける）

  --out reports/video-evidence/large --max-videos 200

# 時系列スコアの採取は元動画取得後。中断時も動画単位のチェックポイントを再利用可能

  --omokage-root /path/to/sekai-nina-omokage \
  --folder reports/video-evidence/large \
  --labels reports/video-evidence/large/reviewed-labels.jsonl \
  --workers 4 --recognition-provider coreml --detection-provider coreml \
  --timeout-sec 3600

# 正解付け後に、未確認がないことを確かめて評価（秒数の指定は不要）

  --input reports/video-evidence/large/videos.jsonl \
  --labels reports/video-evidence/large/reviewed-labels.jsonl \
  --min-hits 2 --min-span-sec 0.5 --max-gap-sec 1 --evidence-bin-sec 0.5 \
  --require-complete --output reports/video-evidence/large/comparison.json
```

参照の一括取得で statement timeout に達したため、500件ずつのページングに変更した。全ページは同じ読み取り専用スナップショットで取得し、参照の上限25,000件を維持する。エラー時は接続情報・署名付きURLを出さず、入力エラーか安全なDBエラーコードだけを出す。

集計には正解の充足数と `evaluationStatus` を明示する。層を均等に抽出したので、単純な正解率や precision を母集団936本の精度と解釈しない。母集団の性能を推定する場合は、保存した抽出確率を使い、回帰用3本を除いて重み付き集計する。最終評価用41本の結果を見て条件を調整したら、別の最終評価用セットを用意する。

正解が揃った後は `scripts/report-video-benchmark.py` で、全200本の推論完了、正解の版、固定した分割を確認して集計する。調整用・最終評価用を分け、旧方式・0.5秒条件・2秒条件を比較する。生の件数と、回帰用3本を除いた抽出確率による重み付き比率を併記する。95% Wilson区間は抽出された動画に対する二項比率の参考区間であり、層別母集団の推定区間や登場確率の校正を示すものではない。
